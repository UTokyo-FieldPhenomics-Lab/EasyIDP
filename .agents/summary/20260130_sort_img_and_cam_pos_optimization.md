# EasyIDP 性能优化报告

## 概述
本报告记录了 `easyidp.Metashape`、`easyidp.Pix4D` 和 `easyidp.reconstruct` 中关键函数的性能分析与优化过程。主要目标是通过利用 NumPy 的向量化能力，消除由 Python 标量循环和冗余计算引起的性能瓶颈。

## 1. `sort_img_by_distance` 优化

### 问题分析
`sort_img_by_distance` 的原始实现（及其辅助函数 `_sort_img_by_distance_one_roi`）存在几个性能问题：
*   **标量循环操作**：它使用标准的 Python `for` 循环遍历每个 ROI 和每个图像，逐个执行距离计算。
*   **冗余计算**：对于每一次图像比较，ROI 多边形的中心点都被重新计算了一次。
*   **低效的数据访问**：在最内层循环中重复进行字典查找和属性访问，增加了显著的开销。

### 优化策略
重构该函数以采用全向量化方法：
1.  **预计算**：将所有相机位置 `(N_cam, 2)` 和 ROI 中心点 `(N_roi, 2)` 提取并一次性预计算为 NumPy 数组。
2.  **向量化距离矩阵**：利用 NumPy 广播机制，一次性计算 *所有* 启用相机与 *所有* ROI 之间的欧几里得距离。
    *   `roi_centers[:, np.newaxis, :] - cam_coords[np.newaxis, :, :]` 创建了一个 `(N_roi, N_cam, 2)` 的差值张量。
    *   沿坐标轴求平方和即可得到距离矩阵。
3.  **流式过滤**：过滤逻辑现在通过高效的数组查找进行操作，而不是重新计算值。

### 基准测试结果 (200 ROIs, 1000 Images)
*   **原始耗时**: ~0.21s
*   **优化后耗时**: ~0.02s
*   **加速比**: **~10x**

## 2. `get_photo_position` 优化

### 问题分析
`get_photo_position` 方法将相机坐标从局部 chunk 坐标系转换到世界（以及可选的项目）CRS。原始实现是线性的：
1.  遍历每张照片。
2.  提取平移向量。
3.  单独调用 `_local2world`。
4.  单独调用 `_world2crs`。

对于包含数千张照片的项目，这由于函数调用成本和 Python 解释器开销而导致了高昂的开销。

### 优化策略
实施了批处理方法：
1.  **批量提取**：将所有启用照片的平移向量 `T` 收集到一个 NumPy 数组 `(N_points, 3)` 中。
2.  **批量转换**：将整个数组传递给 `_local2world` 和 `_world2crs`（这些函数本身已支持向量化操作，但之前只接收单点输入）。
3.  **快速赋值**：仅遍历结果一次，将其赋值回照片对象。

### 基准测试结果 (5000 Photos)
*   **原始耗时**: ~0.80s
*   **优化后耗时**: ~0.004s
*   **加速比**: **~200x**

## 技术原理

### 向量化 (Vectorization)
Python 是一门动态语言，由于类型检查和解释器开销，在大数据集上的循环速度较慢。NumPy 将这些循环推入编译好的 C 代码中，允许对整个数组的操作以接近原生代码的速度发生。

### 广播 (Broadcasting)
广播允许 NumPy 在算术运算期间处理不同形状的数组。在 `sort_img_by_distance` 中，我们从 `(N, 1, 2)` 中减去形状为 `(1, M, 2)` 的数组，从而自动生成 `(N, M, 2)` 的差值数组，而无需编写嵌套循环。

### 减少函数调用开销
Python 中的函数调用有一个虽小但不可忽略的成本。当在循环中调用数千次（例如，每张照片的坐标转换）时，这种成本会累积。无论数据集大小如何，批量输入将此减少为常数次调用。
